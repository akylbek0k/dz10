# 💬 WebSocket Group Chat — Групповой онлайн-чат с JWT авторизацией (ДЗ №10)

Домашнее задание №10: полнофункциональный групповой веб-чат в реальном времени через протокол **WebSocket** с регистрацией, авторизацией и выходом по **JWT** (access / refresh токены), защитой чата от неавторизованных пользователей и автоматическим деплоем на **GitHub Pages** через **GitHub Actions**.

- 🌐 **Демо (GitHub Pages):** [https://akylbek0k.github.io/dz10/](https://akylbek0k.github.io/dz10/)
- 📖 **Swagger REST API:** [https://inai-col3.fishrungames.com/api/docs/](https://inai-col3.fishrungames.com/api/docs/)
- ⚡ **WebSocket Gateway:** `wss://inai-col3.fishrungames.com/chat/`

---

## 🚀 Основные возможности

### 1. Авторизация по JWT (Access + Refresh)
- **Регистрация (`POST /api/register/`)**:
  - Валидация логина по правилам бэкенда (`^[\w.@+-]+$`, до 150 символов).
  - Пароль от 6 символов, валидация совпадения паролей.
  - Мгновенное получение access-токена в ответе и refresh-токена в `HttpOnly` cookie.
- **Вход в систему (`POST /api/login/`)**:
  - Аутентификация пользователя, сохранение access токена и профиля.
- **Выход (`POST /api/logout/`)**:
  - Полный logout: удаление сессии на сервере, очистка токена на клиенте и корректный разрыв WebSocket-соединения.
- **Автоматическое обновление токена (`POST /api/token/refresh/`)**:
  - Если access токен истек (или WebSocket вернул ошибку `4003 Invalid Token`), клиент бесшовно запрашивает новый токен через cookie и восстанавливает соединение без потери контекста.

### 2. WebSocket Чат в реальном времени (`wss://inai-col3.fishrungames.com/chat/`)
- **Протокол рукопожатия (Handshake AUTH):**
  - При открытии соединения клиент отправляет:
    ```json
    {
      "type": "AUTH",
      "payload": {
        "token": "<JWT_ACCESS_TOKEN>"
      }
    }
    ```
  - При успехе сервер возвращает подтверждение:
    ```json
    {
      "type": "AUTH_SUCCESS",
      "payload": {
        "username": "user1"
      }
    }
    ```
- **Отправка сообщений:**
  ```json
  {
    "type": "CHAT_MESSAGE",
    "payload": {
      "text": "Всем привет!"
    }
  }
  ```
- **Получение входящих сообщений:**
  ```json
  {
    "type": "NEW_MESSAGE",
    "payload": {
      "sender": "user1",
      "text": "Всем привет!",
      "timestamp": 1794203092682
    }
  }
  ```

### 3. Разграничение доступа (Безопасность)
- **В чате могут писать только авторизованные пользователи**:
  - Неавторизованным пользователям поле ввода заблокировано и отображается стильная плашка с кнопками быстрого входа и регистрации.
  - Попытка подключиться к WebSocket без токена или с неверным токеном отсекается сервером (код 4003).

### 4. Современный интерфейс и UX
- 🎨 **Современный темный дизайн** в стиле Telegram / Discord / Linear с плавными анимациями и адаптивностью под мобильные устройства.
- 🟢 **Индикатор статуса сети** в реальном времени (В сети / Авторизация... / Подключение... / Отключено) с автоматическим переподключением при обрывах связи.
- 🔔 **Звуковые уведомления** для новых входящих сообщений через синтезированный Web Audio API (не требует внешних mp3-файлов) с кнопкой включения/выключения звука.
- 👤 **Генеративные градиентные аватары** с инициалами пользователей на основе хэша логина.
- 💬 **Умная группировка сообщений**: идущие подряд сообщения от одного автора объединяются.
- ⬇️ **Плавающая кнопка прокрутки вниз** со счетчиком непрочитанных сообщений, если пользователь прокрутил историю наверх.
- 🔍 **Поиск по сообщениям**: быстрый фильтр по автору или тексту.
- 😀 **Панель быстрых эмодзи и реакций** (👍, ❤️, 🔥, 😂, 🎉, 🚀, 👏, ✨).
- ⚙️ **Окно настроек сервера**: возможность просмотра протокола и переопределения URL API / WebSocket при необходимости.

## 💻 Локальный запуск

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/akylbek0k/dz10.git
   cd dz10
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Запустите dev-сервер:
   ```bash
   npm run dev
   ```

4. Откройте в браузере `http://localhost:3000`.

## 🚢 Сборка и Деплой

Сборка production-бандла:
```bash
npm run build
```

Готовые файлы компилируются в папку `dist/`. Деплой на GitHub Pages происходит автоматически через GitHub Actions при пуше в ветку `main` (файл `.github/workflows/deploy.yml`).
